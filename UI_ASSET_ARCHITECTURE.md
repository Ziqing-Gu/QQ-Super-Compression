# QQ Super Compression — UI Asset Architecture

## v0.9.2 architectural change

v0.9.2 is the first build where the rotary control **appearance is no longer generated by JUCE vector drawing**.

The user explicitly rejected the previous code-generated glow approach because it could produce a functional UI but not the intended product-level material/light quality. The chosen direction is a real image-asset workflow similar to traditional audio-plugin filmstrips/sprite sheets.

## Runtime rotary asset

Runtime asset:

`Assets/Knobs/QQSC_MainKnob_128Frames_256_VERTICAL.png`

- 128 frames.
- Frame size: 256 x 256 px.
- Transparent PNG.
- Vertical filmstrip.
- Embedded into the plug-in binary with `juce_add_binary_data`; the installed plug-in does not depend on an external asset file path.
- Ratio, Makeup, Mix, Input Gain and Output Gain all use the same asset family in v0.9.2; Input/Output are rendered smaller by layout, not by a separate low-resolution bitmap.

### Frame mapping

```text
frame = round(normalizedParameterValue * 127)
```

The 128 images are **visual frames only**. They do NOT quantise the actual parameter.

- Mouse dragging remains continuous at the APVTS parameter's normal precision.
- DAW automation remains continuous at the parameter's normal precision.
- Host/controller mapping can naturally line up with ordinary 7-bit MIDI CC values 0..127.
- The visual frame simply shows the nearest of 128 states.

This distinction must not be removed by a future AI in an attempt to make the value "match the sprite exactly".

## Numeric text must NOT be baked into the PNG

The user specifically requires editable values.

The image asset contains only:

- knob body/material;
- rotating pointer;
- progressive illuminated arc;
- local shadow/light spill.

The following remain live JUCE text/UI rendering:

- digits 0-9;
- decimal point `.`;
- minus/plus signs;
- ratio colon `:`;
- `%`;
- `dB`;
- parameter names/labels.

This preserves direct text entry, HiDPI text clarity, localization flexibility and exact values such as `7.95 dB` even though the knob picture has only 128 visual states.

## Light behaviour

The user clarified this repeatedly and it is a hard visual rule:

- Pointer remains visible at both frame 0 and frame 127.
- The warm orange edge light is **cumulative**, not a single moving lamp.
- It starts at the minimum/left side of the usable rotary sweep.
- At about 20%, only the first about 20% of the usable arc is lit.
- As value rises, the lit section grows continuously from left/minimum toward the pointer.
- At 100% / frame 127, the complete usable rotary arc is illuminated.
- Unreached arc remains off.

The usable sweep is 270 degrees, leaving the familiar lower gap of a rotary control.

## Visual style

The target is the warm, clean, transparent, modern domestic/industrial design direction approved by the user:

- warm ivory / sand surface;
- low-profile, faceted/bevelled body rather than soft inflated plastic;
- restrained orange light rather than dark cyberpunk/neon;
- clear geometry and material separation;
- light is a product detail, not the dominant visual effect.

## Buttons

v0.9.2 changes **rotary controls only** to bitmap assets.

A/B, copy, Match, Bypass, Mode, Oversampling and ComboBox remain vector/JUCE controls for this candidate because their bitmap state assets have not yet been separately approved. Do not silently invent final button sprites just for consistency; their asset transition should happen only after visual approval.

## Replaceability

The asset loading is intentionally isolated inside `UTF8LookAndFeel::drawRotarySlider()`.

A future approved filmstrip can replace the PNG while leaving:

- APVTS parameter IDs/ranges;
- SliderAttachments;
- Undo/Redo;
- text editing;
- DSP;
- A/B state;

unchanged.
