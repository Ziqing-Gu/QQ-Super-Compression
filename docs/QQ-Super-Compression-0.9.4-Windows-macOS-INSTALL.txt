2. Choose the correct archive
-----------------------------

1. Windows 64-bit VST3
   QQ-Super-Compression-0.9.4-Windows-x64.zip

2. Native macOS Apple Silicon VST3 (M1/M2/M3/M4 and later)
   QQ-Super-Compression-0.9.4-macOS-Apple-Silicon-VST3.zip

3. Native macOS Intel VST3
   QQ-Super-Compression-0.9.4-macOS-Intel-VST3.zip

4. macOS Universal 2 AU (contains both arm64 and x86_64)
   QQ-Super-Compression-0.9.4-macOS-Universal-AU.zip

The Windows package was built and validated on GitHub Actions windows-2022 and is intended for 64-bit Windows 10/11 VST3 hosts. Older Windows versions are unverified.

The Apple Silicon VST3 was built and validated on macOS 14 arm64. The Intel VST3 was built and validated on macos-15-intel x86_64. The Universal 2 AU was verified to contain both arm64 and x86_64 and passed auval. The Info.plist does not declare a minimum macOS version, so untested earlier systems must not be treated as supported.

macOS packages are ad-hoc signed. They are not Apple Developer ID signed and are not Apple-notarized.

3. Required preparation
-----------------------

1. Save your projects.
2. Fully quit Cubase, Nuendo, Studio One, REAPER, Logic Pro, every other DAW, and all plug-in scanners.
3. If an older version is installed, back up its bundle if you may need to roll back.
4. Find and remove old duplicate bundles so the host cannot scan multiple locations, show duplicates, or keep loading an old cache.
5. Preserve each complete .vst3 or .component bundle while extracting. These bundles appear as folders in the file system; do not copy only the internal binary.

4. Windows 64-bit VST3 installation
-----------------------------------

1. Extract:
   QQ-Super-Compression-0.9.4-Windows-x64.zip

2. Confirm that the complete bundle exists:
   QQ Super Compression.vst3

3. With administrator permission, copy it to the system VST3 directory:
   C:\Program Files\Common Files\VST3\

4. The final path should be:
   C:\Program Files\Common Files\VST3\QQ Super Compression.vst3

5. If Windows asks to merge or overwrite, first confirm that every DAW is fully closed, then overwrite the old bundle. If overwrite fails, move the old bundle out first and copy the new one. Do not keep “QQ Super Compression.vst3”, a version-suffixed copy, and another duplicate in a different scan path.

6. Start the DAW and perform a full VST3 rescan. In Cubase, use Plug-in Manager. If the old version still appears, close Cubase, clear that host's plug-in blacklist/cache, restart, and scan again.

7. Confirm version 0.9.4 in the plug-in information or small UI version label.

5. macOS VST3 installation
--------------------------

Important: the Apple Silicon and Intel VST3 archives are two architecture builds of the same format. Install only one; do not install both.

- On an Apple Silicon Mac running the DAW natively, prefer the Apple Silicon VST3.
- On an Intel Mac, install the Intel VST3.
- On Apple Silicon, consider the Intel VST3 only when you intentionally run an Intel DAW under Rosetta. DAW and plug-in architectures must match.
- AU is an independent format and may be installed alongside the one selected VST3.

1. Extract the selected VST3 archive to obtain:
   QQ Super Compression.vst3

2. In Finder, hold Option while opening the Go menu to reveal the user Library. You may also use Go to Folder.

3. Choose one installation location:

   Current user (normally no administrator password):
   ~/Library/Audio/Plug-Ins/VST3/

   All users (normally requires an administrator password):
   /Library/Audio/Plug-Ins/VST3/

4. Example final paths:

   ~/Library/Audio/Plug-Ins/VST3/QQ Super Compression.vst3

   or:

   /Library/Audio/Plug-Ins/VST3/QQ Super Compression.vst3

5. Before installing, remove or move old same-name bundles from both locations and check custom VST3 folders. Keep only one VST3 with the required architecture.

6. Restart the DAW and perform a full VST3 rescan. If using Rosetta, confirm that the DAW's “Open using Rosetta” setting matches the installed VST3 architecture.

6. macOS Universal 2 AU installation
------------------------------------

AU and VST3 are independent formats. Logic Pro primarily uses AU. Installing AU does not replace VST3.

1. Extract:
   QQ-Super-Compression-0.9.4-macOS-Universal-AU.zip

2. Confirm:
   QQ Super Compression.component

3. Copy it to one location:

   Current user:
   ~/Library/Audio/Plug-Ins/Components/

   All users (normally requires an administrator password):
   /Library/Audio/Plug-Ins/Components/

4. Remove old same-name components, then restart Logic Pro or another AU host.

5. In Logic Pro, open Plug-in Manager, locate Qing Audio / QQ Super Compression, and reset/rescan it if required. The AU identity is:
   Type: aufx
   Subtype: Qscp
   Manufacturer: Qing

7. macOS quarantine and notarization notice
-------------------------------------------

Because the packages are not Apple-notarized, macOS may block the plug-in on first load. If macOS explicitly says that the developer cannot be verified, and you have confirmed that the archive comes from this project's trusted public release/delivery, remove quarantine only from this plug-in bundle.

Current-user VST3:

xattr -dr com.apple.quarantine "$HOME/Library/Audio/Plug-Ins/VST3/QQ Super Compression.vst3"

System VST3:

sudo xattr -dr com.apple.quarantine "/Library/Audio/Plug-Ins/VST3/QQ Super Compression.vst3"

Current-user AU:

xattr -dr com.apple.quarantine "$HOME/Library/Audio/Plug-Ins/Components/QQ Super Compression.component"

System AU:

sudo xattr -dr com.apple.quarantine "/Library/Audio/Plug-Ins/Components/QQ Super Compression.component"

Safety warning:
- Run these commands only after confirming the file source and SHA-256.
- The path must point exactly to the single QQ Super Compression bundle.
- Never recursively remove quarantine from the entire Downloads, Library, VST3, or Components directory.
- Do not disable Gatekeeper or use broader system-security bypasses.
- Restart the DAW and rescan after running the command.

8. Upgrade, duplicates, and compatibility
-----------------------------------------

- You may overwrite the same-name bundle when upgrading. Parameter IDs and state compatibility remain unchanged.
- Arbitrary Lookahead values saved by 0.1.4 migrate to the nearest 0/10/26/40/80/100 ms preset, choosing the longer preset on an exact tie.
- A new instance remembers the user's last Lookahead choice; the fallback is 26 ms when no history exists.
- In 0.9.4, Oversampling is visible and active only at Lookahead=0 ms; the button cycles 1x/8x/16x and the remembered default is 8x.
- At Lookahead=10/26/40/80/100 ms, the control is hidden and DSP is fixed at 1x. Returning to 0 ms restores the previous choice.
- Version 0.1.8-or-earlier states without Oversampling migrate to 8x. Version 0.1.9 old 1x remains 1x, while old 2x/4x/8x migrate to 8x.
- Do not keep one copy in the user VST3 directory and another in the system directory. Do not install both arm64 and x86_64 VST3.
- If the DAW still displays an old version, close it, remove duplicate bundles, clear the host cache/blacklist, and rescan.
- The measurable harmonic distortion at 0 ms Lookahead is an intentional flavour, not a hidden fault.
- Changing Lookahead changes reported latency, so the host may perform a one-time PDC realignment during playback.
- Bypass uses the same delayed path and does not silently become zero latency.
- Version 0.9.4 remains Candidate/Test. It must not be marked Stable until Cubase GUI, listening, automation, project restore, and final user acceptance are complete.

9. Recommended first validation
-------------------------------

1. Confirm that the host displays QQ Super Compression 0.9.4.
2. Test ST, LR, and MS modes.
3. Switch through 0/10/26/40/80/100 ms and observe host delay compensation.
4. At 0 ms, confirm that the Oversampling button offers only 1x/8x/16x and check 8x/16x CPU, PDC, Mix, and Bypass alignment. The button should hide at non-zero Lookahead.
5. Confirm that increasing Ratio increases Gain Reduction and that Makeup, Mix, and Bypass work.
6. Confirm that Integrated LUFS Match becomes available after at least one complete 400 ms measurement block.
7. Check the 2-second GR Peak Hold and verify that changing Mode/Lookahead clears stale markers.
8. Resize the editor and confirm that the complete UI keeps the original 1020x670 aspect ratio.
9. Save and reopen a project, then verify parameters, A/B, Mode, Lookahead, and editor-size restore.
10. Make a copy before testing old production projects.

10. Troubleshooting
-------------------

- Not scanned: verify the directory, match the bundle architecture to the DAW, confirm that the complete bundle was copied, and perform a full rescan.
- Blacklisted: close the DAW, clear that host's blacklist/cache, then scan again.
- Blocked by macOS: confirm source and hash first, then use the xattr command only on the single bundle.
- Duplicate entries: remove duplicate bundles from user, system, or custom scan paths and keep one VST3 architecture.
- Old version remains: close the DAW, remove the old bundle and cache, copy 0.9.4, restart, and rescan.
- Unexpected sound or behaviour: record the DAW, OS, architecture, sample rate, buffer, Mode, Lookahead, reproduction steps, and a minimal project excerpt, then submit an issue in the public repository.
